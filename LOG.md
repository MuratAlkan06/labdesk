## 2026-09-21 22:54 PDT — Slice S1: data and logic foundation

- **built**: `.gitignore`, `requirements.txt` (streamlit>=1.52, pytest>=8.0, matplotlib>=3.9), `core.py`, `seed.py`, `conftest.py`, `tests/test_core.py`, and a working `.venv` on Python 3.14.6 (resolved to streamlit 1.64.0, pytest 9.1.1, matplotlib 3.11.2). `core.py` holds every constant (CATEGORIES, PRIORITIES, SOURCES, STATUSES, TECHNICIANS, ALLOWED_TRANSITIONS, DEFAULT_DB), the tickets/notes schema, and the Submit/Queue/Triage/Dashboard functions; it imports only sqlite3, statistics, contextlib and datetime. `seed.py` resets the database and inserts 30 hand-written lab tickets and 19 technician notes spread over the last 30 days. Verification: `.venv/bin/pytest -q` → `28 passed in 0.11s`; `.venv/bin/python seed.py` twice → identical `Seeded labdesk.db: 30 tickets, 19 notes.` and exit 0 both times; `grep -n streamlit core.py` empty; `python3 -c "import core"` works outside the venv; `grep -rn "SET status" *.py tests/*.py` matches core.py only (3 lines, all inside `change_status`). Demo shape checked against the seeded database: statuses 8 Open / 5 In Progress / 7 Resolved / 10 Closed, workload Priya 5 / Diego 3 / Hannah 2 / Unassigned 3, oldest open led by a 12-day High and an 11-day Urgent, zero tickets resolved before creation or in the future.
- **error-and-fix**: The §13 no-rankings gate failed on my own code. `grep -in "rank\|leaderboard\|fastest" core.py seed.py` printed `core.py:336: Deliberately absent: anything ranking technicians by resolution speed` and `core.py:337: (PRINCIPLES.md §1). Workload counts open work, never who is fastest.` — the `dashboard_metrics` docstring explained the ban using the exact words the gate greps for, so a clean implementation would have tripped the check. Reworded to "any per-technician resolution-speed comparison ... Workload counts open work only." The grep is now empty (exit 1) across core.py, seed.py and tests/test_core.py. No other errors: pytest was green on its first run and both seed runs exited 0 on the first attempt.
- **decision**: A near-empty `conftest.py` sits at the repository root so `tests/test_core.py` can `import core` and `import seed`. Under pytest's default prepend import mode the directory containing a standalone conftest.py is added to sys.path; the rejected alternatives were `sys.path` surgery inside the test file (noisier) and a `pytest.ini`/`pyproject.toml` with `pythonpath` (a config file this project otherwise does not need).
- **decision**: `core.UNASSIGNED = "Unassigned"` is a named constant because the string is load-bearing in two places — the `list_tickets(assignee=...)` filter and the dashboard workload bucket. Rejected: retyping the literal, which is the same failure mode §2 guards against for statuses.
- **decision**: `core.is_valid_transition(from_status, to_status)` exists as the boolean predicate §4 names by example; `change_status` calls it instead of testing the set inline, and the Triage UI can reuse it later. Rejected: inlining the membership test, which would have left §4's named predicate unimplemented.
- **decision**: `dashboard_metrics` returns `by_status`, `by_priority`, `workload` and `by_source` pre-filled with every constant at zero, so a chart keeps stable categories when a bucket empties. `by_source` maps each source to `{"count": int, "share": float}` with share as a 0–1 float (formatted as a percentage only at render time, per §8); `avg_resolution_hours` is returned unrounded and is `None` when no ticket has a `resolved_at`. Rejected: separate `by_source_counts`/`by_source_shares` keys, which would have put the same total in two places.
- **decision**: core raises `ValueError` naming `ticket_id` when `add_note`, `assign_ticket` or `change_status` is handed an id that does not exist, and rejects empty note authors/bodies. §7 makes core the authority on validity, and the alternative — a `TypeError` from indexing a `None` row — is exactly the traceback §6 forbids showing a user.
- **decision**: `get_conn` issues `PRAGMA foreign_keys = ON` so the `notes.ticket_id` reference is enforced rather than decorative. Rejected: leaving SQLite's default off, which lets orphan notes exist.
- **decision**: `seed.py` reads the clock only through `datetime.fromisoformat(core.now_iso())` and never calls `datetime.now()` itself, keeping §5's single time seam intact while still needing a real datetime for the 30-day arithmetic. It also aliases `OPEN, IN_PROGRESS, RESOLVED, CLOSED = core.STATUSES` and `PRIYA, DIEGO, HANNAH = core.TECHNICIANS` instead of retyping those strings (§2), and imports no sqlite3 — it borrows `core.get_conn` for its historical INSERTs (§3).
- **decision**: `random.seed(RANDOM_SEED)` is the first statement of `seed_database()` rather than a module-level call, so two calls in one process (as in the determinism test) produce byte-identical data, not just equal row counts. Verified: seeding two temp databases in one process yields identical titles, statuses, assignees and times of day.
- **decision**: Ticket content, status, assignee, age and resolution time are hand-written per ticket in `TICKET_SEEDS` rather than drawn randomly, so full coverage of categories/priorities/sources/statuses and the uneven workload are guaranteed by construction; randomness only picks each ticket's time of day. A `_check_seed` guard rejects an unknown category/priority/source/status/assignee, a non-Open ticket with no assignee, and any ticket that would resolve in the future — a typo in demo data fails loudly at seed time instead of quietly breaking a filter during the demo.
- **decision**: Five tests beyond the eight the slice specified: notes list oldest-first, `assign_ticket` rejects a non-technician, `get_ticket` returns None for an unknown id, `avg_resolution_hours` is None with nothing resolved, and the seeded data covers every category/priority/source/status. They cover core functions that the eight required tests otherwise left unexercised.
